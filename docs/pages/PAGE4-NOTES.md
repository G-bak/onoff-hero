사용자가 제공한15초 영상을 중심으로 만든 WEB 페이지다. 로컬 주소 http://localhost:5187/#web. 기존 DESIGN은 승인된 편집 지면을 유지하고 소개하는 인물만 추가했다. 기존 마케팅은5페이지 #card 그대로다. 커밋·push·배포하지 않았다.

## 현재 구성

검정 #090A0F·흰 글자·중립적인 회색 구분선·라임 진행률. 후속 요청으로 왼쪽 가장자리에 깔린 파란 ::before 장식을 삭제하고 오른쪽 파란 구분선도 흰색의27% 투명도로 바꿨다. 큰 WEB 제목, 고객 문의로 이어지는 / 우리 회사 홈페이지, 가로 영상, 다섯 장면 선택, 웹 담당 인물을 배치했다.5페이지의 세 광고판이나3페이지의 인쇄 지면을 재사용하지 않는다. 영상은 자르지 않고16:9 전체를 표시한다. 초기 무음 자동 재생, 재생/일시정지, 소리, 키보드 조작 가능한 타임라인,0·4·7·10·13초 장면 이동을 지원한다.

오른쪽 문구는 **업종에 맞게 기획하고 / 필요한 기능을 만듭니다**, 인물 아래는 **제작부터 유지보수까지**다. 영문은 WEB DEVELOPMENT와 BUILD & SUPPORT로 같은 서비스 내용을 표현한다. 추상적인 경험·시작·그다음 대신 문의, 업종, 기능, 유지보수라는 고객의 구체적인 관심사를 쓴다. [디지트미](https://digitme.co.kr/)의 문의 동선·업종 분석·필요한 기능·운영 설명과 [WEB198](https://www.web198.co.kr/)의 업종별 첫 화면·메뉴·문의 동선·관리자 기능 설명을 조사해 직접 작성했다. 해당 업체의 성과나 가격을 ON&OFF의 것으로 쓰지 않았다.

후속 사용자 지시로4페이지가 한 화면에 들어오도록 높이도 반영했다. 섹션은100svh, 제목·푸터는 실제 높이, 나머지 공간은 영상과 인물 영역으로 배정한다. 데스크톱 영상 너비는 남는 높이에서 조작부128px를 뺀16:9 크기와 실제 가용 너비 중 작은 값이다. 낮은 가로 화면은 제목·조작부·소개를 간결하게 바꾸고, 휴대폰은 영상 아래에 인물을 둔다. 높이760px 이하 휴대폰은 제목과 문구를 가로로 배치해 인물·재생 조작이 서로 겹치지 않게 한다. 공통 우측 메뉴/프로젝트 문의 링크은 한 번만 렌더링하며 하단 여유를 확보한다.

WEB→MARKETING 전환에만 SectionEntry의 scrollRatio=0.8을 적용했다.100svh 화면 크기와 이동 궤적은 보존하고 넘기는 데 필요한 스크롤을20% 줄인다.1440×900에서는900→720px이며 #web은3600px 그대로, #card는4500→4320px이다. getSectionScrollLength가 전환 진행률·스크롤 여백·중첩 앵커의 동일한 길이를 계산한다. 긴 화면의 일반 읽기 구간은 줄이지 않고, 움직임 감소와 JavaScript 미사용은 원래 문서 높이를 유지한다. 휠·터치 입력을 가로채지 않는다.

## 재생과 자산

최신 재생 버그 수정: 페이지를 마우스로 넘기다 WEB 화면이 드러난 곳에서 멈추면 영상과 버튼이 잠겨 있었다. 높이가 긴 DESIGN은 sticky 위치에서 이미 위로1350px 이동한 상태로 추가 회전/이동한다. 그런데 `getSectionEntry`는 실제 앞면이 사라져도 명목상 #web 앵커까지 `covered=false`를 유지해 뒤쪽 WEB을 inert로 잠갔다. 실제1440×900에서 scrollY3480은 DESIGN 하단이 화면 위125px까지 나갔지만 앵커는570px 남아 있어0초·0프레임으로 멈췄다.

`lib/section-entry.ts`는 sticky 이동과 회전 후 가장 낮은 모서리가 화면을 벗어나는 시점에 앞면을 가려진 상태로 처리한다. 기존 이동 궤적·문서 높이·앵커 위치·인디케이터 진행률은 유지한다. 역방향에서는 그 모서리가 다시 나타날 때 앞면과 입력 상태를 복구한다. 움직임 감소는 기존 일반 문서 경계를 따른다. 초기 재생 요청 복구만 보완한 직전 변경으로는 이 스크롤 구간의 잠금을 해결하지 못했다.

- `app/components/web-section.tsx`, `app/web-cinema.css`: WEB 전용 화면, 영상 상태·장면·반응형.
- `app/components/person-motion.tsx`, `lib/person-motion.ts`, `app/components/use-scene-activity.ts`, `app/people-motion.css`: 현재 WEB은 원본 인물을 다시 참조한 v5 실제12포즈다. 가로형 슬레이트 칠판과 은색 금속 테두리로 교체하고 WEB 쓰기→밑줄→물러서 확인→지우기를2760ms로 반복한다. 글씨·분필·손이 래스터에 함께 들어 있으며 이전 SVG 낙서와 마스크는 제거했다. 긴 리브 니트·안경·원본 체형을 참고하며 받침대가 없다. 작은 컷은 사용자가 허용한 범위로 남아 있다. 마지막 자세 유지 정책은 SYSTEM에만 적용한다. [v5 원본·프롬프트·검토](../../design/people-motion/v5/README.md).
- `lib/web-film-playback.ts`: 초기 재생 중단 후1회 복구, canplay/loadeddata 준비 상태 확인, 오래된 재생 Promise 무효화. 클릭 안에서 즉시 play를 호출해 사용자 활성화를 유지한다. 정책 차단 때는 수동 재생을 표시하고 반복 재시도하지 않는다. 수동 정지는 페이지를 나갔다 돌아와도 유지한다.
- `app/page.tsx`: WEB도 active/covered 상태를 전달한다. 기존 여섯 중첩 SectionEntry와7항목 연속 메뉴는 유지한다.
- 영상은 preload=none으로 HOME 초기 다운로드를 피하고 WEB이 실제 보이며 조작 잠금이 풀리면 재생한다. 가려짐·탭 숨김·화면 밖·MOTION OFF에서는 영상과 인물을 멈춘다. 로딩 안내, 재생이 차단됐을 때 수동 시작, 파일 오류의 재시도 UI를 제공한다.
- 움직임 감소는 포스터와 최종 인물 자세. 사용자가 직접 누른 영상 재생은 허용한다. JavaScript가 없으면 기본 video controls가 남는다.
- 원본 영상은 다른 프로젝트에 그대로 보존했다.1280×720과15.04초를 유지하며13.3MB→3.1MB로 압축했다. 출처·프롬프트·생성 기준은 [영상 기록](../../design/web-showcase/README.md), [인물 기록](../../design/people-motion/README.md).
