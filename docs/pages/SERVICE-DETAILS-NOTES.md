# 네 서비스 상세페이지 개선 — 2026-09-13

## 요청과 범위

사용자: “다른 상세페이지도 타사 홈페이지나 경쟁사 쪽은 어떻게 했는지 보고 좀 전문적으로 만들어봐.”

대상은 `/services/planning`, `/services/design`, `/services/marketing`, `/services/operations`다. 직전 승인된 `/services/web` 전용 페이지, 홈페이지 일곱 섹션, 7페이지 제목의 92% 배율과 프로젝트 문의 16px, 상담톡 숨김 상태를 보존한다. 로컬 작업이며 커밋·push·배포하지 않는다.

## 조사와 적용

2026-09-13 공식 홈페이지의 서비스 설명·작업 분류·운영 안내를 조사했다. 조사 목적은 전문 업무의 범위와 고객의 판단 기준을 구체화하는 것이다. 경쟁사의 고객 실적·성과·가격·자산을 온앤오프의 것으로 사용하지 않는다.

공식 페이지는 웹 도구와 렌더링된 본문으로 확인했다. BAT의 일반 브라우저 접속은 오류가 있었지만 웹 조회로 공식 페이지 내용을 확인했다. `outputs/service-reference-*` 초기 캡처에는 일부 사이트의 로더가 남아 있으므로, 이를 완성 화면의 시각 비교 자료로 사용하지 않는다. 전체 사이트를 그대로 복제하는 작업이 아니다.

## 구현

- `lib/services.ts`: 기존 서비스 목록·요약·메타데이터 원본 유지.
- `lib/service-details.ts`: 네 서비스의 상세 산출물, 진행 단계와 고객 확인 사항, 견적 유형, 추가 비용, FAQ, 문의 준비 자료. 서비스 slug를 타입으로 검사한다.
- `professional-service-detail.tsx`: 표지 → 필요성·효과 → 작업 범위·예시 → 진행 과정 → 견적 기준 → FAQ → 문의 → 다른 서비스·푸터의 공통 서버 템플릿.
- `service-detail-visuals.tsx`: 서비스별 설명에 맞는 별도 시각 자료. 기획서·실행안, 업종별 디자인, SNS·블로그·매장 광고, 요청 처리·범위 비교.
- `service-details.css`: `.service-guide`·`.guide-*`에 한정한 스타일. 기존 홈과 웹 상세의 클래스를 재사용해 덮어쓰지 않는다.
- `/services/[slug]`: 웹 전용 분기를 보존하고 나머지 네 서비스만 새 템플릿에 연결한다. 잘못된 slug는 404.

표지는 대형 Montserrat 영문과 Pretendard 한글, 라임·파랑·기존 디자인 핑크를 사용한다. 내용이 많은 장은 표·단계·짧은 목록으로 읽을 수 있게 구분했다. 모바일은 고정 축소 화면 대신 열 수와 배치를 변경한다. 고객이 읽는 새 안내 문구는 12px 미만으로 줄이지 않는다.

기획은 고객·메시지·채널·실행을 담은 실제 읽을 수 있는 HTML 기획서 예시다. 디자인은 베이커리·뷰티·리빙 세 시안을 사용처와 함께 보여준다. 마케팅은 피드의 계정·이미지·본문·반응 영역과 블로그의 제목·작성 정보·본문을 HTML로 구성한다. 데이터는 기존 `lib/marketing-content.ts`를 재사용한다. 피드의 사진은 원본 720×900이며, 홈페이지 캔버스의 720×1420과 혼동하지 않는다. 블로그도 원본 이미지와 HTML 본문을 구분한다. 유지관리는 실시간 대시보드를 가장하지 않고 ‘업무 흐름 예시’로 안내한다.

## 자산과 판매 조건

기존 승인된 `app/assets/design-showcase/`와 `app/assets/marketing/` 이미지만 사용했다. 새 이미지 생성·경쟁사 이미지 복사는 하지 않았다. [기존 마케팅 자산 기록](../../design/marketing/v3/README.md)의 가상 브랜드와 예시 반응 수 표기를 유지한다. 실제 고객 사례·실적이 아님을 예시 옆과 표지 캡션에서 밝힌다.

가격과 계약 조건을 새로 확정하지 않는다. 기획·디자인·마케팅은 작업 유형을 선택하는 안내이며, 유지관리는 월 관리·건별 지원을 비교한다. 상담 후 견적, 수량·수정 범위·일정·세금·결제 조건 확인을 안내한다. 매체 집행비와 제작·운영비, 유료 자산·촬영·인쇄비, 외부 서비스 이용료를 구분한다. 특정 매출·노출 보장, 무제한 수정·즉시 복구·24시간 대응을 임의로 약속하지 않는다.

유지관리 안내는 기존 웹 가격 자료 v4의 미확정 상태와 맞췄다. 월 작업 건수나 지원 기간을 고정하지 않고, 신규 페이지·기능과 데이터베이스 백업·복구는 별도 협의한다. 상세한 원본 검토는 [WEB-SERVICE-NOTES.md](WEB-SERVICE-NOTES.md)에 있다.

## 이동·모션·준비 상태

기존 `ServiceDetailMotion`의 실제 글꼴·표지 이미지 준비 UI, 한 번의 제목·내용 등장, 활성 목차·읽기 진행선을 사용한다. 새 표지 시각 자료는 준비 후 한 번 원근을 풀며 등장한다. 반복 흔들림이나 긴 스크롤 고정 구간, 새 WebGL 장면·의존성은 추가하지 않았다.

장 부모를 관찰하는 기존 등장 감지를 유지한다. 움직임 감소·탭 비활성·JS 미사용 처리를 보존하며, FAQ는 네이티브 `details`다. 기존 `#why-service`, `#service-effects`, `#service-scope`, `#pricing`를 보존하고 과정·FAQ 목차를 추가했다. `PageLink`와 상세의 즉시 페이지 이동, 직접 해시·뒤로가기 위치를 유지한다. 문의 링크는 해당 서비스가 선택된 기존 UI로 연결되며 실제 문의 전송 기능을 추가하지 않았다.

검증 스크립트·로그·화면은 Git에서 제외되는 `outputs/service-guides-*`, `outputs/guide-*`에 저장한다. 별도 영구 테스트를 추가하지 않고 기존 필수 검사와 실제 브라우저 동작을 확인했다.

- 승인된 웹 상세의 세 제작 유형·스타일 보존, 잘못된 서비스 주소의 실제 404 확인. 검사 중 페이지 런타임 오류 0건.
- 완료 결과: `outputs/qa/2026-09-13/services/service-guides-qa.json`의 `passed: true`. 데스크톱 표지·작업 예시와 모바일 본문·가격·과정 화면을 별도로 열어 시각 확인했다.

로컬은 기존 Node/Vite 미리보기다. 이 환경의 Windows 정책으로 차단된 Cloudflare workerd 런타임 검증을 대체하지 않는다. 배포 설정과 OS 정책은 변경하지 않았다.
