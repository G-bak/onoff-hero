## 최신 수정 · 상세페이지 진입 스크롤

서비스 바로가기를 누르면 새 상세페이지가 이전 스크롤 위치에서 맨 위까지 약 2,900px를 부드럽게 역주행하던 문제를 재현했다. 전역 `html { scroll-behavior: smooth }`가 App Router의 `scrollTop = 0`에도 적용된 것이 원인이다. 기존 `data-scroll-behavior="smooth"` 표기만으로는 설치된 Vinext의 App Router 경로에서 이 동작을 막지 못했다.

서비스 상세 또는 별도 문의 페이지가 DOM에 있을 때 루트 스크롤을 `auto`로 전환한다. CSS가 새 지면의 첫 레이아웃부터 적용되므로 마운트 후 타이머로 다시 위로 올리거나 화면을 숨기지 않는다. 홈페이지의 승인된 섹션 전환·부드러운 메뉴 이동은 보존한다. 별도 페이지 내 목차는 해당 항목으로 즉시 이동하며 브라우저 뒤로가기의 저장 위치와 직접 `#pricing` 주소도 보존한다. 상세의 제목·사진 등장 모션은 바꾸지 않는다.

CSS 전환만 적용했을 때에는 이전 홈페이지에서 이미 시작한 부드러운 스크롤의 마지막 프레임 때문에 약 9~15px가 남는 경우도 재현했다. `app/components/page-link.tsx`는 실제 클라이언트 이동이 시작되는 `onNavigate`에서 현재 위치를 유지한 채 그 스크롤을 즉시 중단한다. 이후 새 페이지의 시작 위치는 라우터가 처리한다. 서비스 목록과 상세 내부의 페이지 링크에 이 컴포넌트를 사용한다. 클릭 시 이전 화면을 먼저 맨 위로 올리지 않으며 새 탭·수정키 클릭과 네이티브 링크 동작을 유지한다.

재현·회귀 검증: `outputs/qa/2026-09-13/services/service-scroll-before.json`, `outputs/qa/2026-09-13/services/service-scroll-after.json`. 최종 빌드 로그: `outputs/qa/2026-09-13/services/service-scroll-ci.log`.

검증 완료: 실제 서비스 목록 클릭 및 관련 서비스 이동으로 상세 5종 모두 새 지면 첫 프레임부터 `scrollY=0`을 유지했다. 모바일 목록 클릭도 동일하다. 가격 목차·직접 `#pricing` 진입·브라우저 뒤로가기의 저장 위치 복원·상세에서 문의 화면으로 이동도 통과했다. 브라우저 오류 0건. `npm run ci:build`의 린트·타입·71개 테스트·프로덕션 빌드·CSS/자산 검사도 통과했다. 로컬만 반영했으며 배포하지 않았다.

## 최신 수정 · 이른 등장과 준비 UI

MARKETING 면이 완전히 넘어가야 사진·문구가 보이던 진입 조건을 수정했다. 기존 공통 `useSceneActivity`의 `duringTransition` 옵션으로 면 전환 중에도 장식 요소의 등장을 시작한다. 링크·버튼은 공통 `SectionEntry`의 `inert` 보호를 그대로 따른다. 화면 밖과 MOTION OFF·움직임 감소 처리는 유지한다.

처음에는 고정된 사진·문구 대신 별도의 준비 UI를 표시한다. 섹션에 접근하면 선택 가능한 이미지들을 준비하고 `document.fonts.ready`와 이미지 `decode()` 완료 후 다음 프레임에 등장한다. 임의 최소 지연은 없다. 실패 또는 12초 지연 시 본문을 열고 이미지 영역에 재시도 버튼을 제공하며, JS 미사용에서는 서버 본문을 바로 보여준다. 상세 페이지의 기존 2.4초 준비 정책은 별개다. 아래 v2 기록보다 이 정책이 우선한다.

실제 휠로 진입할 때 메뉴가 아직 MARKETING인 상태에서 SERVICES가 등장하는 것을 확인했다. 이미지 응답 지연 중 `data-ready=false`, 준비 UI 표시·본문 숨김을 확인했고, 요청 실패 후 재시도로 이미지가 복구됐다. 호버는 변환 없이 기존 교차 페이드를 유지한다. 캡처는 `outputs/qa/2026-09-13/services/services-early-reveal.png`, `outputs/qa/2026-09-13/services/services-preparing.png`다. 전체 최신 검증은 [PAGE7-NOTES.md](PAGE7-NOTES.md)에 기록한다.

## 후속 수정 · 호버 효과 완화

사용자가 다른 디자인은 승인하고 호버 효과만 이전의 단순한 방식으로 요청했다. 서비스 선택마다 반복되던 콜라주의 큰 이동·회전·클리핑과 티켓 펼침, 검정 띠 와이프를 제거했다. 이미지 구성은 0.2초 교차 페이드로 바뀌고 목록 배경은 0.2초, 작은 화살표·텍스트 반응은 기존 0.25초 ease를 사용한다. 입체적인 콜라주·목록·타이틀의 첫 등장과 상세 페이지는 유지한다. 모든 콜라주 레이어의 첫 등장 타임라인이 같으므로 선택해도 펼침이 다시 시작되지 않는다. 로컬만 반영했다.

브라우저에서 빠르게 다섯 서비스를 오가며 이미지가 교차 전환되고 큰 변환·클리핑이 재시작되지 않음을 확인했다. 키보드 선택·상세 이동·목록 복귀와 상세의 기존 등장 모션도 확인했다. 빌드 검증 로그는 `outputs/qa/2026-09-13/services/services-hover-ci.log`다.

## 화면과 콘텐츠

기획·전략, 브랜드·디자인, 웹사이트, 콘텐츠·마케팅, 운영·유지관리의 다섯 분야를 안내한다. 라임 #D8FF3E 배경과 #090A0F/#FFFFFF 글자, 로컬 Montserrat/Pretendard를 사용한다. 최신 제목은 대형 **SERVICES**이며, 안내는 “한 가지 작업부터 통합 운영까지. 필요한 서비스를 골라보세요.”다. 왼쪽은 승인된 포트폴리오 이미지를 사용한 인쇄물 콜라주, 오른쪽은 큰 영문 서비스명·한글 이름·상시 설명의 목록이다. 제목은 순차적 압축·신장·반동으로, 목록은 원근을 가진 면처럼 등장한다. 행 호버/포커스는 단순 배경·화살표 반응과 서비스별 이미지 교차 페이드를 사용한다. 행 전체가 하나의 링크다. 모바일에서도 그림을 유지하고 한 열의 일반 문서 스크롤을 사용한다. 추가 감상 스크롤은 없다. 고객이 읽는 설명·조작 문자는 최소 12px이며 작은 그림 내부 글자는 장식이고 스크린리더에서 제외한다.

상세 페이지는 서비스별 표지색·큰 배경 타이포·작업물 콜라주, 두 줄 제목 등장, 순차적인 본문 펼침으로 구성한다. 기대 효과는 검정 지면, 가격 정책은 흰 견적서, 문의는 파랑이다. 서비스별 소개·필요성·효과·제공 범위·가격 정책·관련 서비스 콘텐츠를 보존한다. 고정 목차는 현재 장을 표시하고 헤더 아래 진행선은 읽기 위치를 따른다. 이메일은 자동 발송하지 않는다. 홈의 3D 장면·로더를 넣지 않고, 상세의 글꼴·표지 이미지 준비 중에만 가벼운 준비 UI를 사용한다. 임의의 최소 대기 없이 준비되면 시작하며 최대 대기 2.4초 후 본문에 접근할 수 있다. 제목은 등장 후 고정된다.

### 가격 정책은 확정 금액이 없는 안내 초안

금액·수정 횟수·납기·최소 계약 기간을 임의로 확정하지 않았다. 각 서비스에 맞는 **개별 견적 기준**을 안내한다. 기획은 조사와 산출물 범위, 디자인은 종류·수량과 연계 작업, 웹은 페이지·기능·자료 준비 상태, 마케팅은 채널·수량·기간, 운영은 월 관리 범위·주기·추가 개발 여부다. 외부 비용·부가세·최종 포함 범위는 견적 시 확인하도록 안내한다. 확정 가격과 계약 조건을 받으면 요약은 `lib/services.ts`, 네 서비스 상세는 `lib/service-details.ts`, 웹 상세는 `lib/web-service.ts`에서 함께 맞춘다. 마케팅 성과를 보장하는 문구는 넣지 않았다.

## 구조와 유지보수

- `lib/services.ts`: 서비스 요약·공통 설명·메타데이터·조회. 네 서비스의 구체 상세는 `lib/service-details.ts`, 웹 전용 상세는 `lib/web-service.ts`가 담당한다.
- `app/components/services-section.tsx`, `app/services.css`: 반응형 서비스 데스크, 목록/상세 모션과 공통 스타일. `useSceneActivity`로 화면·inert·MOTION OFF·움직임 감소 상태를 공유한다.
- `app/components/service-artwork.tsx`: 다섯 서비스의 사진 면·티켓·스티커. 기존 해시 자산 주소를 재사용하고 CONCEPT VISUAL 표기를 제공한다. 새 래스터 이미지나 라이브러리를 추가하지 않았다.
- `app/components/service-detail-motion.tsx`: 초기 준비, 장별 등장, 목차·읽기 진행, 탭 숨김 정지와 해제, 움직임 감소, 정리. IntersectionObserver는 클리핑한 자식이 아닌 장 컨테이너를 관찰한다. 클리핑한 요소 자체를 관찰하면 영원히 교차하지 않아 본문이 숨는 문제가 생긴다. `noscript`는 준비 UI 없이 본문을 드러낸다.
- `app/services/[slug]/page.tsx`: 서버에서 상세 콘텐츠와 페이지별 메타데이터 제공, 알려진 5개 slug 생성. 잘못된 slug는 `notFound()`로 실제 404와 목록 복귀 화면을 제공한다.
- 내부 이동은 `next/link`, 미리 가져오기는 꺼서 목록만 보는데 모든 상세 경로를 미리 요청하지 않는다. 외부 이메일·본문 목차는 일반 링크다.
- `app/page.tsx`의 MARKETING 다음에 `SectionEntry id="services" scrollRatio={0.8}` 추가. 앞의 카드 감상 길이·동작은 유지한다. 새 면에 완전히 가려진 MARKETING은 `covered`로 쉬며, 돌아오면 이전 장면 시간을 이어간다.
- `lib/site-sections.ts`에 여섯 번째 메뉴를 추가했다. 전환 수는 목록 길이에서 계산한다. 현재 공통 메뉴 7개·프로젝트 문의 링크를 한 번씩 렌더링하며 상담톡은 숨긴다.
- 루트의 `data-scroll-behavior`만으로는 해결되지 않았다. 현재는 `html:has(.service-detail, .inquiry-page)`의 `scroll-behavior:auto`와 `PageLink`의 진행 중 스크롤 중단을 함께 사용한다. 상단 최신 스크롤 수정 기록을 따른다.
- 브라우저의 기본 아이콘 요청을 위해 기존 32px PNG를 픽셀 변경 없이 ICO 컨테이너에 담은 `public/favicon.ico`를 추가했다.
