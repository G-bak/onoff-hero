## 연결과 운영

- 흐름: 문의 화면 → 같은 출처의 `/api/inquiry` → `https://formspree.io/f/mqpawbdg` → Formspree에 설정된 수신 이메일.

- 기존 Slack용 환경값은 더 이상 읽지 않는다. Slack으로 병행 전송하거나 실패 시 대체 전송하지 않는다. 기존 secret은 롤백 가능성을 위해 이 작업에서 삭제하지 않는다.
- 공개 폼 주소와 명시적 정책 버전 `2026-09-29`를 서버 경로에서 함께 배포한다. 이전 환경 정책 버전은 사용하지 않으며, 클라이언트·서버의 안내와 버전이 일치해야 접수할 수 있다.

## 전달 내용과 결과

`name`, `email`, `message`, 고정 제목 `subject` 및 회사·연락처·서비스·예산·예산 기준·일정·참고 자료·한국시간 접수 시각·접수 ID·동의 기록을 JSON으로 보낸다. 고객 본문과 참고 자료는 원문을 보존한다. 고객 IP나 임의 수신자 필드는 전달하지 않는다.

`Accept: application/json`과 문의 페이지 Referer를 사용한다. HTTP 200 및 JSON `ok: true`를 모두 확인해야 앱이 접수 완료를 표시한다. 리디렉션과 비정상 상태는 실패로, 응답 불명·네트워크 단절·시간 초과는 접수 불명으로 처리하고 자동 재전송하지 않는다. Formspree 접수 성공은 실제 메일함 도착 확인과 구분한다.

기존 입력 검증, 요청 크기 제한, 출처 검증, 같은 실행 인스턴스 내 중복 억제 및 과다 요청 제한을 유지한다. 이는 영구 접수 저장소나 분산 중복 방지 보장은 아니다.

## 개인정보와 확인

동의 안내를 Formspree 기준으로 갱신했다. 기존 최대 90일 관리 방침은 유지하며 담당자가 Formspree 접수 내역과 수신 이메일·업무 사본을 관리·삭제한다. 자동 삭제 기능을 추가하거나 서비스 보관 한도를 늘린 것은 아니다.

서버 테스트는 필드 보존·회신 주소·한국시간·응답 판정·중복·실패·시간 초과와 기존 검증을 확인한다. 전체 검사는 `npm run ci:build`다. 실제 테스트 문의와 운영 배포 결과는 로컬 업무일지에 기록한다.
