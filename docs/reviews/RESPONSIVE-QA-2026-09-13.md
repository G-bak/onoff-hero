## 수정 후 검증

- 기본 117조건에서 문서 가로 넘침, 보이는 텍스트의 가로 잘림, 12px 미만 안내 글자, 이미지 누락, 실행 오류가 없었다. 홈 최종 컨트롤 검사에서도 메뉴·버튼 차단이 없었다.
- 상세 일부 링크는 0.8초 전환과 최대 0.21초 순차 지연 중 검사되어 원시 JSON에 일시 차단이 남았다. 해당 9개 경로·화면·스크롤 조합을 1.8초 대기 후 다시 검사했고 모두 `blocked:[]`였다.
- 초기 작은 화면 HOME 캡처 일부는 로더 해제 전 스크롤 때문에 SYSTEM을 담았다. 검사 도구가 로더 DOM 제거까지 기다리도록 수정하고 최종 9개 크기를 모두 다시 촬영했다. 초기 잘못된 캡처는 HOME 판정에서 제외했다.
- WEB 667×320 하단 추가 검사에서 챕터 5개 모두 hit test 통과, 푸터 하단은 화면 내 304px였다.
- 320·375·844px 문의폼에서 빈 값 오류 5개, 다중 서비스, 긴 소개·링크·한글 파일명, 파일 선택·제거와 내부 스크롤을 확인했다. 확인창 clientWidth/scrollWidth는 각각 **288/288, 343/343, 680/680px**. 하단 버튼이 모두 보이고 실제 전송 버튼은 비활성이다.
- 확인창은 Escape로 닫히고 종료 애니메이션 후 작성 내용 확인 버튼으로 포커스가 돌아온다. 닫기 직후 중간 프레임을 포커스 실패로 판단하지 않았다.
- 상세 5개에서 320·844px의 FAQ를 모두 펼쳤다(총 42개 펼침). 가로 넘침 없음.
- 상세 5개의 하단 문의 링크를 실제 클릭했다. 문의가 scrollY 0에서 열리고 해당 서비스가 미리 선택됐다.
- HOME 오프닝을 320×568, 390×844, 768×1024, 1440×900에서 재생했다. 390×844에서는 재생 중 844×390으로 회전했다. 모두 메인 연결·잠금 해제·오프닝 캔버스 제거·워드마크 opacity 1 확인.
- Chromium DPR 1→2→1 변경 시 앞·뒤 카드 캔버스는 CSS 너비 1283px에 대해 1283→2566→1283px로 함께 갱신됐다.
- 375×667의 HOME·마케팅 상세·웹 상세·문의에서 움직임 감소와 JavaScript 미사용 표본 8개를 검사했다. 본문 표시·가로 넘침 없음·잠금 없음. HOME 7개 섹션 유지, JS 미사용 문의 입력 비활성.
- MOTION OFF에서 TOGETHER 안내가 정적으로 표시되고 닫은 뒤 프로젝트 문의 링크로 포커스가 복귀했다.
- 수정 후 대표 캡처 7장을 별도로 다시 확인해 SYSTEM·DESIGN·SERVICES·WEB·마케팅 상세·320px 푸터의 지적 사항이 해소됐음을 확인했다.
- `npm run ci:build` 통과: 저장소 검사, lint, TypeScript, 기존 회귀 테스트 90개(실패 0), 프로덕션 빌드, CSS·자산 검사 완료. 최종 문서 검사도 75개 문서·275개 로컬 링크 경로·10개 public 파일을 통과했다. 기존 대형 번들·중복 자산 파일명 경고와 Vinext 경로 분류 안내는 남아 있다. 신규 실행 오류는 없었다.
- 최종 로컬 HOME을 다시 열어 HTTP 200, HOME 활성, 카드 캔버스 2개, MOTION ON, 오프닝 종료·잠금 해제·가로 넘침 없음을 확인했다. 기존 5187 서버를 유지했다.
