# 주소 해시 없는 섹션 이동 — 2026-09-15

사용자가 `#home` 등 섹션 주소를 없애고 사이드 메뉴의 스크롤 이동만 유지하도록 요청했다.

## 동작

- 사이드 메뉴7개, 홈 로고, WEB 다음 섹션 링크와 상세·문의의 페이지 내 목차를 누르면 해당 위치로 이동한다. 주소를 바꾸거나 섹션별 방문 기록을 추가하지 않는다.
- 홈은 기존 CSS의 부드러운 스크롤, 상세·문의는 기존 즉시 이동을 유지한다. 움직임 감소는 즉시 이동한다.
- 상세·문의에서 홈으로 돌아오는 링크는 기존 `PageLink` 라우팅과 진행 중 스크롤 중단을 유지한다. 도착한 페이지의 대상 위치를 맞춘 뒤 주소의 해시를 제거한다. 경로·쿼리·라우터 history state는 유지한다.
- 기존 `/#services`, `/#together`, `/#film` 같은 주소로 들어와도 목적지로 이동한 뒤 해시를 지운다. HOME은 준비 화면이 스크롤 잠금을 해제한 뒤 처리한다. 준비 중 섹션 선택은 오프닝을 종료하고 마지막으로 선택한 위치로 이동한다.
- 뒤로가기·앞으로가기의 해시 없는 주소에서는 강제 이동하지 않고 기존 라우터의 저장 위치 복원을 사용한다.
- 키보드와 본문 건너뛰기는 목적지에 포커스를 옮기고, 임시 `tabindex`는 포커스 이탈·정리 시 제거한다. 원래 있던 `tabindex`는 보존한다.
- JavaScript 미사용과 새 탭 열기를 위해 HTML의 `href`와 섹션 ID를 유지한다. JS 미사용 상태에서는 브라우저의 기본 해시 이동을 사용한다. Ctrl/Cmd/Shift 클릭·다운로드·외부 링크는 가로채지 않는다.

## 구현

`app/layout.tsx`에 공통 `app/components/scroll-navigation.tsx`를 연결하고 `lib/scroll-navigation.ts`에서 같은 페이지 링크를 처리한다. `usePathname`으로 라우터 이동 후 진입 주소를 확인하며 직접 해시 변경·popstate도 처리한다. HOME 준비 UI를 기다리는 동안만 DOM 변경을 관찰하고, 이동·페이지 이탈·언마운트 때 예약 프레임과 이벤트를 정리한다.

`HeroOpening`은 주소를 바꾸지 않는 섹션 선택 신호에도 종료한다. `SectionEntry`의 예전 `#film` → `#together` 주소 치환은 제거하고 기존 SSR 별칭 앵커는 유지한다. 면 전환 좌표·높이·등장·메뉴 현재 위치 계산은 바꾸지 않는다.

직전 운영 상세 탭·완료 체크와 전체 장식 화살표 제거를 보존한다. 로컬 반영이며 커밋·push·배포하지 않는다.

## 검증

- `npm run ci:build`: 테스트153개·린트·타입·빌드·CSS/자산 검사 통과.
- 새 이동 테스트9개에서 메뉴7개·기존 해시/별칭·HOME 준비 대기·준비 중 목적지 변경·상세에서 홈 복귀·키보드 포커스·움직임 감소·해시 없는 뒤로가기·기본 링크 예외·이벤트 정리를 확인했다.
- 기존 오프닝 컴포넌트 검증에 섹션 선택 시나리오를 추가해 HOME 선택은 유지하고 다른 섹션 선택은 종료·GPU 정리하는지 확인했다.
- 로컬7개 경로 HTTP200과 공통 이동 모듈 연결을 확인했다. 설치된 Vinext의 링크 처리에서 `defaultPrevented`를 존중하고 경로 상태는 라우터 커밋 후 갱신되는 것을 확인했다.
- 위 동작 검증은 제어된 테스트 환경이며 실제 브라우저 클릭·뒤로가기·시각 검수는 이번에 수행하지 않았다.
