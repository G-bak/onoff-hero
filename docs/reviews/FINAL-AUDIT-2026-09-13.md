# 2026-09-13 최종 전체 검사

사용자의 “전체 프로젝트 검사한번 쫙 진행하고 마무리하자” 요청에 따라 코드·문서·자산·빌드·문의 보안·운영 화면을 다시 점검했다. 확인한 결함을 수정하고 기존 디자인·오프닝 시간표·Slack 알림 양식·개인정보 기준을 보존했다. 이전 검사와 구분한 이번 검증 범위와 결과다.

## 수정한 문제

### 문의 전송 전 브라우저 호환성 오류

기존 폼은 `crypto.randomUUID()`를 오류 처리 밖에서 호출했다. 이 API가 없는 환경에서는 실제 POST 없이 전송 중 상태와 닫기 잠금이 남았다. `AbortSignal.timeout()` 미지원 환경도 요청을 보내기 전에 접수 여부 불명으로 분류됐다. 브라우저에서 두 조건을 주입해 재현했다.

- [ID 생성](../../lib/inquiry-request-id.ts)은 네이티브 UUID를 우선하고, 미지원이면 안전한 난수 바이트로 UUIDv4를 만든다. `Math.random()`을 사용하지 않는다.
- [문의 폼](../../app/components/project-inquiry.tsx)은 준비 작업까지 오류 처리 안에 두고 `AbortController`·15초 타이머를 사용하며 종료 시 타이머를 정리한다.
- 전송 전 준비 실패에는 재시도·닫기가 가능하다. 실제 요청 후 응답 불명에는 자동 재전송하지 않고 이메일 확인을 안내한다. 중복 클릭은 즉시 차단하며 Slack 접수 ID와 서버 정책은 유지한다.
- [회귀 검사](../../tests/ui-state.test.mjs)에 네이티브 바인딩·안전한 UUID 대체·난수 실패 두 검사를 추가했다.

### 문서와 산출물 경로

README와 문서 색인에 남아 있던 “로컬만 반영”이라는 현재 상태 설명을 실제 GitHub·운영 반영 이력과 구분했다. `check:repository`의 제목 앵커 검사와 별도 외부 URL 검사도 정확히 설명했다. 마케팅·인물 문서의 이전 루트 PAGE 문서 경로를 고쳤고, 15개 문서의 이동된 `outputs/` 경로를 실제 날짜·분야 폴더에 맞췄다. 과거 테스트 수치와 디자인 이력은 지우지 않았다.

기존 [디렉터리 기준](../README.md)과 [outputs 분류](../operations/OUTPUTS.md)를 유지한다. 이번 결과는 Git 제외 `outputs/qa/2026-09-13/final-audit/`에 모았으며 승인된 원본·비교 자료·이웃 프로젝트를 삭제하거나 이동하지 않았다.

## 실제 브라우저 검사

운영 주소의 Chromium에서 1440×900, 375×812, 320×568, 768×1024, 844×390을 사용했다. 실제 iOS/Android 기기를 사용한 결과는 아니다.

- 홈 7개 섹션 이동·HOME 복귀의 40상태: 오프닝 종료, 활성 메뉴 1개, 섹션 입력 잠금 해제, SYSTEM·MARKETING 렌더 준비, TOGETHER 영상 준비와 안내를 확인했다. 각 크기에서 MOTION OFF/ON도 조작했다.
- 다섯 서비스 상세와 문의 페이지 30조건: 응답·제목·첫 진입 위치·전체 스크롤·깨진 이미지·서비스별 문의 연결·웹사이트 미리 선택·이메일·상담톡 숨김을 확인했다.
- 375×812에서 움직임 감소와 JavaScript 미사용의 홈·상세·문의 14조건, 잘못된 서비스·보관 자산 URL의 실제 404 두 조건을 확인했다.
- JavaScript 미사용 HOME의 첫 자동 측정은 스타일 로딩 전에 실행돼 가로 넘침으로 표시됐다. 이 측정 시점을 재현하고 `load`·`document.fonts.ready` 후 위 다섯 화면 크기에서 실제 넘침 0·본문 7섹션·로더 숨김·잠금 해제를 확인했다. 검사 스크립트의 준비 조건을 고쳤으며 제품 CSS는 변경하지 않았다. 원래 실패 로그와 보완 검증을 함께 보관한다.
- 문의 수정은 로컬 375×812·1000×850에서 UUID API 미지원, timeout API 미지원, 안전한 난수 실패, 네트워크 실패, 빠른 두 번 클릭의 10조건을 검사했다. 동의 두 항목 전 차단·POST 횟수·성공 후 잠금·준비 실패 시 닫기·네트워크 불명 안내가 모두 예상대로 동작했다. 모의 POST만 사용해 추가 Slack 메시지는 보내지 않았다.

정상 화면의 수평 넘침과 브라우저 실행 오류는 확인되지 않았다. 모든 프레임과 모든 기종을 보장하는 결과는 아니며 [이전 반응형 QA](RESPONSIVE-QA-2026-09-13.md), [추가 엔진 QA](MAINTENANCE-2026-09-13.md), [실제 Slack 접수 검증](../operations/SLACK-INQUIRY.md)과 이번 범위를 구분한다.

## 유지할 운영 기준과 검증 한계

- 문의 내용은 Slack으로만 보낸다. 무료 Slack의 개인정보 보관은 기존 기준대로 매주 문의 채널의 80일 이상 기록·사본을 수동 정리하고, 처리 완료·삭제 요청은 더 일찍 처리한다. 자동 삭제가 구현된 것으로 안내하지 않는다.
- 중복·요청 제한은 Worker isolate 메모리의 10분 보조 장치이며 재시작·여러 isolate를 아우르는 영구 접수 시스템은 아니다.
- 현재 메타데이터의 `noindex, nofollow`와 준비 중인 채용·소식은 기존 상태다. 검색 공개·확정 요금·판매 조건을 이번 검사에서 임의로 바꾸지 않았다.
- 실제 모바일 Safari·가상 키보드·실기기 터치는 이번에 검증하지 않았다. 로컬 Node 미리보기는 이 PC의 workerd 실행 차단을 대체하는 UI 확인이며 운영 Worker 검증과 구분한다.
