### 수정 기록 — 2026-09-09

- 사용자 요구: 처음 ON으로 시작한다. OFF는 자동 회전만 멈추며, 마우스·터치 드래그와 키보드 조작은 유지한다.
- 변경 전에는 움직임 유무와 관계없이 매 프레임 두 WebGL 화면을 다시 그렸다.
- 이제 자동 회전 중이거나 카드 회전·마우스 기울기가 목표 위치로 이동 중일 때만 다음 프레임을 예약한다. 미세한 움직임이 충분히 작아지면 목표 위치에 맞춘 뒤 예약을 멈춘다.
- 드래그·방향키·포인터 이동 및 이탈·버튼 해제·크기 변경·ON/OFF·방향 전환 시 필요한 프레임을 다시 예약한다. 연속 입력은 한 프레임 예약으로 모아 중복 루프를 방지한다.
- 탭이 숨겨지면 예약을 취소하고, 돌아오면 그리기를 재개한다. 쉬었던 시간이 회전량에 누적되지 않도록 프레임 시간을 초기화한다.
- OS 움직임 감소 설정 변경과 WebGL 컨텍스트 복원도 다시 그리는 계기로 연결했다. 2번에서 유지하기로 한 ON 표시 및 OS 설정의 기존 의미는 바꾸지 않았다.
- 자원 정리 시 프레임과 이벤트 구독을 해제하고, 뒤늦은 호출로 루프가 재시작되지 않도록 했다.

- Chrome 152에서 실제 `WEBGL_lose_context` 손실·복원을 일으켜 개발 서버와 로컬 프로덕션 Worker에서 각각 10가지 시나리오를 통과했다. 단일·양쪽 손실, 부분 복구 대기, MOTION OFF, 시간 초과, 수동 기본 화면, 재시도, 렌더링 예외, 모바일을 확인했다. 페이지 오류 0, 주입한 예외에 대한 의도된 앱 경고 외 콘솔 오류·경고 0. 복원 후 실제 카드 표시도 스크린샷으로 확인했다.
- 상세 정책·재현 방법·검증 한계: [RECOVERY-NOTES.md](../operations/RECOVERY-NOTES.md). 숨겨진 탭의 시간 계산은 단위 테스트로 확인했으며 실제 드라이버 충돌이나 모든 기기를 검증한 것은 아니다. 커밋·GitHub push·운영 배포는 하지 않았다.

## 최초 검토 결과와 한계

### 후속 화면 구현 — 2026-09-10, 로컬만 반영

두 번째 시안 구현과 사용자 반응형 수정 지시를 반영했다. 별도 헤더 DOM은 삭제했다. 최종 수정에서는 페이지 전체의 고정 비율을 제거하고 첫 화면처럼 너비 100%와 화면 높이를 기준으로 배치한다. 좁은 화면은 Grid 흐름으로 재배치한다. 12개 화면 크기에서 본문 경계·가로 넘침·데스크톱 첫 화면과의 높이 일치를 검사했다. 가려진 첫 화면의 3D 렌더링과 복구 제한 시간도 쉬도록 연결했다. 총 37개 테스트와 빌드가 통과했으며 상세 기준과 브라우저 검증은 [PAGE2-NOTES.md](../pages/PAGE2-NOTES.md)에 기록했다. 기존 4~7번 로컬 수정은 보존했으며 커밋·push·배포는 하지 않았다.

아래 내용은 최초 검토 시점의 기록이다.

- 타입 검사: `node node_modules/typescript/bin/tsc --noEmit --incremental false` 통과.
- 기존 로딩 테스트: `npm run test:loading` 5개 통과.
- 기존 빌드 결과의 CSS 검사: `node scripts/check-production-css.mjs` 통과.
- CSS 검사의 9개 화면 크기 확인은 계산 기반이다. 실제 브라우저에서 9개 화면을 검증한 것은 아니다.
- 로컬 서버의 `/` 요청은 HTTP 200으로 응답했다.
- 연결 가능한 브라우저가 없어 클릭, 모바일 레이아웃, WebGL 장애를 직접 검증하지 못했다.
- 개발 작업에 영향을 주지 않도록 새 전체 빌드와 배포는 실행하지 않았다.
- 상담톡은 최신 수정에서 입력·전송이 비활성화되고 이메일 문의가 안내된다. 이전의 ‘입력은 되지만 전송되지 않는 상태’를 현재 문제로 기록하지 않는다.
- 회사 임시 정보, 뉴스·채용 준비 상태, 검색엔진 `noindex`는 개발 중인 범위로 구분한다. 공개 전 실제 정보와 공개 정책을 확인할 항목이다.

## 설명 및 진행 순서

1. 보안 의존성이 무엇이고 현재 프로젝트에 어떤 의미인지 설명한다.
2. 모션 표시 불일치와 불필요한 렌더링을 각각 설명한다.
3. 글자 가독성과 첫 화면 로딩을 설명한다.
4. 린트 검사와 3D 장애 복구를 설명한다.
5. 1번과 3번은 배포까지 처리했고 2번은 사용자 요청으로 기존 동작을 유지한다. 4~7번은 로컬 수정·검증을 마쳤다. 7번에서 데스크톱·모바일 크기의 Chrome 화면 및 실제 컨텍스트 장애 재현을 확인했으며, 전체 기기별 시각 검증과 로딩 시간 실측은 남아 있다. 최초 목록에서 새로 착수할 미수정 항목은 없고, 실측 후 성능 개선과 배포 전 최종 확인을 이어갈 수 있다. 새 변경은 배포 요청이 있을 때 GitHub push와 자동 배포를 진행한다.
