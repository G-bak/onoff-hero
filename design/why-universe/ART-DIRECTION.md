# WHY 3D 아트 디렉션과 실행 계획 — 2026-09-11

> 폐기된 매듭·지휘자 연출의 보관 이력이다. 현재 SYSTEM 은하·인물은 [은하 기획](../galaxy/ART-DIRECTION.md)과 [인물 기준](../galaxy-crew/README.md)을 따른다. 과거 생성 명령으로 현재 구현을 대체하지 않는다.

요청: 초안의 메시지를 유지하면서 전문적인 실시간 3D 브랜드 연출로 재설계. 이 문서는 구현 전에 작성한 조사·판단·실행·검증 기준이다. 작업 범위는 2페이지이며 1페이지·3페이지·공통 메뉴·면 전환·인물 8포즈를 보존한다. 로컬 확인 단계, 배포하지 않는다.

## 현재 초안의 문제

1. 네 개의 납작한 압출 조각이 평면 아이콘처럼 보여 금속 입체감이 약하다.
2. 세 개의 일정한 타원이 원자 모형에 가까우며 밝기·밀도가 거의 같다.
3. 조립·회전이 유사한 속도로 진행되고 여운·가속·정착의 차이가 작다.
4. 환경광과 전면광이 균일해서 반사광·어두운 면의 대비가 부족하다.
5. 별·서비스 노드·배경 입자가 비슷한 수준의 디테일이라 중심 형상보다 장식으로 읽힌다.

## 새 아트 방향: 하나의 흐름으로 엮이는 금속 리본

- 중심은 네 개의 **입체적으로 꼬인 금속 리본 구간**이 맞물려 하나의 연속된 조형을 만드는 형태다. 곡면에 두께·완만한 모서리·안팎 면·겹침이 보여야 한다. 범용 납작한 별 모양은 교체한다.
- 은색 크롬이 주재질이고, 좁은 라임 발광 선과 코발트 반사가 브랜드 포인트다. 전체를 흰색·네온으로 태우지 않는다.
- 원형을 그대로 반복하지 않는 비대칭 공간 경로를 사용한다. 가는 바탕 선 위로 밝은 신호와 꼬리가 흐르고 입체 별이 앞뒤를 통과한다.
- 배경은 검은 네이비 중심의 낮은 밝기 구름과 미세 입자. 큰 오브젝트 주위에만 빛을 모으고 글자 뒤는 어둡게 유지한다.
- 제목 `다른 감각, 하나의 방향.`과 짧은 설명을 유지한다. 형태가 결합되는 시점에 제목이 펼쳐지고 서비스 라벨은 선 연결 뒤에 나타난다. 작은 인물은 같은 장면의 지휘자로 유지한다.

## 연출 시간표

| 시간 | 화면 변화 | 기술 |
| --- | --- | --- |
| 0–0.6초 | 어두운 공간, 응축된 신호와 서로 떨어진 금속 구간 | 낮은 밝기의 점광과 깊이, 구간별 다른 시작 자세 |
| 0.4–2.2초 | 네 구간이 휘어진 경로로 모여 맞물림 | 구간별 시차, 가속/감속, 감쇠되는 정착 움직임 |
| 1.5–3.0초 | 큰 제목 두 줄이 순서대로 드러남 | 마스크·이동·작은 기울기, HTML 글자 유지 |
| 2.1–4.2초 | 궤도가 중심에서 풀려나고 빛 신호가 퍼짐 | 경로 UV 기반 드로잉·움직이는 밝기·잔광 |
| 3.3–4.8초 | 서비스 노드·인물·설명 정착 | 연결 완료 후 정보 등장 |
| 이후 | 느린 조형 회전, 빠르기가 다른 신호, 작은 시점 반응 | 하나의 시간축, 단정한 반복, 숨김/정지 상태에서 휴식 |

## 구현 구조와 비용

- `lib/why-universe.ts`: 시간표·순수 궤도 계산·해상도 예산. 메시·DOM과 분리해 수치 검사 가능.
- `lib/why-universe-geometry.ts`: 동일 경로를 공유하는 리본 구간·모서리·곡선. GPU 형상은 초기화 때 생성하며 매 프레임 재생성하지 않는다.
- `lib/why-universe-scene.ts`: 조명·재질·셰이더·후처리·장면 그리기·자원 정리.
- `app/components/why-universe.tsx`: React의 가시성·접근성·수명과 엔진을 연결. 기존 공통 frame loop를 재사용한다.
- 큰 외부 3D 모델·HDR·동영상·새 라이브러리를 다운로드하지 않는다. 인물의 기존 100KB WebP를 유지한다.
- 캔버스 픽셀 예산을 제한하고 작은 화면은 낮은 DPR과 단순한 후처리를 사용한다. 고해상도 화면의 무조건적인 native DPR은 사용하지 않는다.
- CPU에서 메시를 반복 생성하지 않고 셰이더 uniform과 행렬 위주로 갱신한다. 반복 입자는 한 배치로 그린다.
- HOME/숨김 탭/CARD 뒤에서는 GPU 루프 정지. OFF·움직임 감소에서는 완성된 정지 장면. WebGL 오류·JS 없음은 읽을 수 있는 대체 그래픽. 컨텍스트 복원 때 환경 맵과 후처리 버퍼도 새로 준비한다.

## 완료 기준과 검증 순서

1. 중간 프레임에서 각각 흩어짐·결합·연결 펼침이 눈으로 구분되는지 확인.
2. 정지 화면에서도 전면·안쪽·뒤쪽과 반사광이 보여야 한다. 금속이 회색 플라스틱처럼 보이면 조명·형상을 수정.
3. 제목·노드·인물·상담·메뉴가 1440/2048/768/390/320/가로 모바일에서 겹치거나 잘리지 않는지 확인. 페이지 종횡비는 고정하지 않는다.
4. 일반 실행의 오류 0건, 가로 넘침 0, 루프 정지·재개·HOME 재진입·컨텍스트 복원·움직임 감소·JS 없음 검사.
5. draw call·삼각형·렌더 버퍼 크기를 측정하고 렌더링 비용을 기록한다. 소프트웨어 브라우저 측정값을 실제 모바일 GPU의 60fps 보장으로 바꾸지 않는다.
6. 단위 검사 → 브라우저 움직임·복구·반응형 → `npm run ci:build`. 실패한 항목을 수정한 후 관련 검사만 재실행한다.
7. 설계 기록에 실제 결과·달라진 판단·검증 한계를 갱신하고 로컬 URL을 제공한다. GitHub push·배포하지 않는다.

## 실행 중 확인한 변경

- 공개 Vimeo 플레이어는 이 환경에서 video 요소가 로드되지 않아 재생 프레임을 확인하지 못했다. Lusion의 공식 설명과 프로젝트 화면을 참고했으며 영상을 시청했다고 주장하지 않는다. Hatom·ManvsMachine은 공식 페이지의 실제 화면을 확인했다.
- 리본의 기본 형상을 만들고 브라우저로 확인한 뒤 블룸이 금속 면을 덮는 문제를 발견했다. 강도·반경을 낮추고 임계값을 높였으며, 물리 재질의 어두운 반사 면과 긴 하이라이트가 보이게 조정했다.
- 작은 가로 화면의 라벨이 오른쪽으로 잘리는 문제를 확인해 1100px 이하의 구성과 카메라를 세로 기준으로 통합했다. 700px 이하의 최소 높이는 850px을 유지한다.
- 조립·경로·입자의 형상은 자체 코드이며 새 이미지 생성이나 외부 HDR·모델·영상·의존성 추가는 없었다. 기존 8포즈 인물은 지휘 동작이 새 아트 방향과 맞아 유지했다.
- 실제 측정: 데스크톱 44 draw calls, 40,720 triangles; 작은 화면 30 draw calls, 40,706 triangles. 일반 환경의 콘솔·런타임 오류 0건, 고의로 WebGL을 막은 대체 화면 테스트의 생성 실패 로그는 별도다.
